# FitnessTracker (app)

iOS app shell — **Phase 1b + 1c**. SwiftUI + SwiftData, iOS 26. Depends on the
local [`FitnessCore`](../FitnessCore) package for all training logic.

## What it does (1b)

Onboarding → rule-engine weekly plan → read-only plan view. Fully offline, no AI.

- **Onboarding** (7 steps): goal, experience, body stats, schedule, equipment
  checklist, areas to avoid, review.
- On "Create my plan": the answers become a `FitnessCore.UserContext`,
  `RulePlanBuilder` builds a plan, `PlanValidator` checks it, the plan is
  persisted as a Codable blob.
- **Plan view**: sessions, exercises (names from the bundled catalog), sets ×
  reps, rest, coach notes, weekly volume targets, and the "why this plan"
  rationale.
- **Settings** scaffold: profile summary, regenerate plan, start over.

## What it does (1c) — AI integration

The plan can now be generated by an LLM, with the rule engine as a guaranteed
fallback. Everything is bring-your-own-key and opt-in: with no active provider
the app behaves exactly as in 1b.

- **Provider profiles** (`Settings → AI Coach → Providers`): add / edit / delete
  a `ProviderProfile` (display name, adapter kind, model id, base URL, per-1M-token
  input / output / cached prices, vision flag). One profile is *active* at a time
  ("Set as active"); "Add on-device (free)" one-taps an Apple on-device profile.
  API keys are written to the **Keychain** (`KeychainStore`), never to SwiftData —
  the profile only holds an opaque `apiKeyRef`.
- **Three adapters** behind `FitnessCore`'s `LLMProvider` protocol, built by
  `LLMProviderFactory.make(from:)`:
  - `openAICompatible` — Chat Completions shape, structured output via
    `response_format: json_schema` (strict). Covers OpenAI and any vendor with an
    OpenAI-compatible endpoint (incl. Anthropic's and Gemini's compat endpoints,
    Bedrock-via-proxy). Needs a base URL; key optional.
  - `gemini` — AI Studio `generateContent`, structured output via
    `responseSchema`. Needs an API key.
  - `appleOnDevice` — `FoundationModels` `LanguageModelSession` (guided
    generation). Zero cost; only works on Apple-Intelligence hardware, otherwise
    reports unavailable and the coordinator falls back.
- **`PlanCoordinator`** (`AI/PlanCoordinator.swift`): AI-generate → `PlanValidator`
  → **retry once** with the validation errors fed back into the prompt → **rule-engine
  fallback**. Returns a `CoordinatorResult` carrying the plan, its `PlanSource`
  (`ai` / `ruleEngine` / `fallback`), the validation issues, and a `CallOutcome`
  (token counts). `PlanGeneration.generateAndStore(...)` runs it, persists the
  `StoredPlan`, and writes the cost record. `WeeklyPlan.source` is tracked through
  to storage.
- **Cost ledger**: one `AICallRecord` per generation — provider / model, input /
  output / cached tokens, and `costUSD` **frozen at write time** from the active
  profile's prices (`AICallRecord.cost(...)`). `CostSummary.from(records:now:)`
  aggregates month-to-date / all-time / call count. Surfaced as: the **`$` chip**
  on the plan screen (`CostChip`, "$0.00 this month"), the **Settings → Usage**
  section (this month / all time / AI calls), and the **post-generation note**
  ("Coach updated · ~$0.01", "Used the rule-engine backup", etc.).

### Deferred in 1c (documented, not built)

- **Native Anthropic, Gemini Vertex/GCP (service-account auth), AWS Bedrock
  (SigV4)** adapters — each is one adapter on the existing protocol;
  `openAICompatible` already reaches all three via their compat / proxy endpoints.
- **Vision / `completeWithImage`** — every adapter throws `LLMError.visionUnsupported`;
  real multimodal lands with the InBody feature (Phase 4).
- **Budget cap + `pauseAIWhenOverBudget` toggle** — the ledger and display ship in
  1c; the enforced monthly cap is a small follow-up (one settings field + one check
  in `generateAndStore`).
- **Session-finalization / swap AI calls** — Phase 2 / 3; 1c only wires
  `weeklyPlan` generation.

## Structure

| Path | Responsibility |
|------|----------------|
| `Models/UserProfile.swift` (+ `UserProfile+Mapping.swift`) | SwiftData `@Model` for the onboarding answers; `makeUserContext()` maps it to `FitnessCore` |
| `Models/StoredPlan.swift` | SwiftData `@Model` holding a `WeeklyPlan` as JSON |
| `Catalog/catalog.json` + `BundledCatalog.swift` | bundled **stub** catalog (20 exercises, free-exercise-db raw shape) → `CatalogStore` |
| `Models/ProviderProfile.swift` | SwiftData `@Model` for a provider config (`AdapterKind`, base URL, `apiKeyRef`, model id, prices, vision, `isActive`) |
| `Models/AICallRecord.swift` | SwiftData `@Model` per-call cost ledger row; `cost(...)` does the price math, frozen at write time |
| `AI/PlanCoordinator.swift` (+ `AI/PlanGeneration.swift`) | `UserContext` → AI-generate → validate → retry → rule-engine fallback → `CoordinatorResult`; `generateAndStore` persists the plan + `AICallRecord` |
| `AI/Adapters/` | `OpenAICompatibleProvider`, `GeminiProvider`, `FoundationModelsProvider` — the 3 `LLMProvider` adapters |
| `AI/LLMProviderFactory.swift` | builds the right adapter from an `AdapterKind` / `ProviderProfile` (reads the key from `KeychainStore`) |
| `AI/PlanPromptBuilder.swift` + `AI/PlanDTO.swift` | system/user prompt + `WeeklyPlanDTO` / `planJSONSchema` / `toDomain(weekStartDate:source:)` |
| `AI/CostSummary.swift` + `AI/KeychainStore.swift` | month-to-date / all-time aggregation; Keychain wrapper for BYO keys |
| `Features/Onboarding/` | the 7-step SwiftUI flow + `OnboardingModel` draft state |
| `Features/Plan/PlanView.swift` (+ `CostChip.swift`) | read-only plan rendering + month-to-date `$` chip |
| `Features/Settings/SettingsView.swift` (+ `ProviderProfileListView` / `ProviderProfileEditView`) | profile summary, regenerate, start over, Usage totals, provider-profile management |
| `RootView.swift` | first-run → onboarding; else → latest plan; loads the catalog once |

## Build / run

Open `FitnessTracker.xcodeproj` in Xcode 26+, pick an iPhone (iOS 26) simulator,
⌘R. Tests: ⌘U (or `xcodebuild test -scheme FitnessTracker -only-testing:FitnessTrackerTests`).

## Notes for later phases

- **Xcode 26 defaults the app module to `@MainActor` isolation.** Pure-logic
  helpers (`BundledCatalog`, `PlanCoordinator`) are marked `nonisolated`; SwiftData
  `@Model` tests and `OnboardingModel` tests run `@MainActor`.
- **Local package × "Designed for iPad" destinations:** the app target's
  Supported Destinations were trimmed to iPhone/iPad only. Leaving "Mac
  (Designed for iPad)" / "Apple Vision" on made Xcode's destination
  intersection with `FitnessCore` (iOS + macOS only) empty → no run
  destinations. Don't re-add them without also widening `FitnessCore`'s
  `platforms`.
